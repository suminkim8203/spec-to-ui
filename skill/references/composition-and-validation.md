# 의미 단위 조합과 화면 검증

대표 화면 제작·피드백 반영·확장에 사용합니다. 명세서 → 구조 → 실제 참고 → 대표 화면 → 피드백 → 확장 → 검토 흐름 안에서 적용합니다. 요소의 완성도가 전체 화면의 품질을 보장한다고 전제하지 않습니다.

## 필요한 조건부터 정리하기

해석에 따라 구조나 조작이 달라지거나 실사용 손실이 예상되면 [의도 해석과 실사용 위험 판단](structure-and-decisions.md#intent-and-usability)을 먼저 적용합니다. 확인한 기준과 예상 위험을 조합·검증 조건에 반영하며, 추측을 사용자 결정으로 쓰지 않습니다.

현재 판단에 영향을 주는 항목만 짧게 기록합니다. 사용자 확정 / 문서·코드 사실 / AI 제안·실험값 / 미정을 구분합니다. 아래 묶음 전체를 필수 설문이나 별도 문서로 만들지 않습니다.

| 묶음 | 필요한 경우 기록할 내용 |
|---|---|
| 맥락 | 역할·핵심 작업·대상 화면/상태·도구·보존 조건 |
| 조합과 관계 | 의미 단위·소속/순서·정보 식별·상호 의존·변경 영향 |
| 후보 | 적합/부적합 조건·근거·공통 조건·비교 축·후보 한도 |
| 판단 | 필수 조건·충돌 우선순위·관찰 근거·문제·비교 기준 버전 |
| 반복 | 시작 이유·수정 범위·횟수/시간 등 필요한 한도·정체/종료·복귀 조건 |
| 결정과 결과 | 실제 피드백·유지/변경/미정·위임·버전·사용자가 볼 결과 |

값을 아직 정할 수 없으면 미정과 영향만 적습니다. 개별 시험의 숫자를 모든 작업의 기본값으로 옮기지 않습니다.

## 작은 조합에서 전체로 확인하기

1. 전체 작업과 정보 우선순위를 먼저 정합니다. 부분을 예쁘게 만드는 일이 핵심 행동을 밀어내지 않게 합니다.
2. 문제를 판단할 수 있는 최소 의미 단위를 고릅니다. 예를 들어 버튼은 글자·아이콘·상태의 조합이고, 목록 행은 식별 정보·날짜·상태·행동의 관계입니다. 모든 픽셀이나 글자로 쪼개지 않습니다.
3. 실제 조건에 맞는 소수 후보를 만듭니다. 익숙한 패턴이나 모범 사례는 조건부 후보이며 보편적인 정답이나 스타일 금지가 아닙니다.
4. **요소 자체 → 함께 놓인 관계 → 조작 전후 흐름**을 확인하며 행·영역·페이지로 조합합니다. 상위에서 새 중복·과한 강조·밀도·맥락 문제가 생기는지 봅니다.
5. 문제가 확인되면 관련 하위 단위와 영향 범위만 수정하고 상위 관계를 다시 봅니다. 관련 없는 결정을 초기화하거나 모든 조합을 전수 비교하지 않습니다.
6. 정한 한도에서 마칩니다. 사용자는 의미 있는 전후 차이와 손실을 판단하면 됩니다. 내부 계층마다 투표나 승인을 요구하지 않습니다.

## 입력·선택·탐색 컨트롤의 디자인 통합

입력 필드(text field/textarea), 선택기, 날짜 선택기, 버튼, 페이지네이션 등을 배치할 때는 선택한 전체 UI의 디자인 기준에 맞춰 CSS를 조정합니다. 브라우저·라이브러리의 기본 외관을 그대로 놓는 것으로 마무리하지 않습니다. 공통 스타일을 이미 상속한 요소는 주변과 실제로 맞는지 확인하며, 불필요한 개별 재작성을 강제하지 않습니다.

- 색감·배경·글꼴·테두리·모서리 형태·높이·내부 여백을 화면의 공통 규칙과 맞춥니다. 같은 역할의 요소는 일관성을 유지하고, 주 행동·보조 행동·현재 선택의 위계는 구분합니다.
- 폭과 공간 배분은 입력 내용의 글자 수뿐 아니라 작업 맥락·주변 정보·화면 폭을 기준으로 정합니다. 아이콘과 끝 경계 사이의 여백, 글자와 아이콘의 정렬, 레이블·도움말·오류·초기화/이전·다음 행동의 관계를 함께 조정합니다.
- 닫힌 모습과 함께 해당하는 펼침·선택·호버·포커스·비활성·오류 상태를 확인합니다. 작은 화면과 키보드 조작에서도 글자·아이콘·필수 조작이 가려지거나 잘리지 않아야 합니다.
- 닫힌 필드의 외곽뿐 아니라 연결된 달력·선택 목록·팝업도 디자인 통합 범위입니다. 펼쳐졌다는 사실만 확인하지 말고 패널 배경·테두리·형태·월/항목 탐색·선택/포커스 표현·간격을 서비스의 공통 규칙과 맞춥니다. 실제 열린 화면을 확인하지 못했다면 미검증으로 남깁니다.
- 외관 조정에서 기존 입력 방식과 선택 가능한 범위를 보존합니다. 달력 입력을 고정 날짜 목록으로 바꾸는 등 조작 의미가 달라지는 대체는 CSS 수정으로 취급하지 않습니다. 이미 정해진 방식을 유지하는 구현 수단을 먼저 검토하고, 중요한 방식 변경은 이유·손실을 설명한 뒤 사용자 판단을 받습니다.
- 네이티브 팝업의 제어 제한을 디자인 통합의 자동 예외로 삼지 않습니다. 요청한 외관을 충족하지 못하면 스타일을 조정할 수 있는 달력/선택 컴포넌트 등 대안을 검토합니다. 구현 수단을 바꾸더라도 기존의 직접 입력·선택 범위·초점·키보드 조작·접근 가능한 이름을 보존하고, 사용성·유지 비용과 중요한 손실을 판단합니다. 제약을 고지했다는 이유만으로 요청을 충족했다고 보고하지 않습니다.

## 요소 자체와 배치 관계

**행의 정렬:** 가로 정렬과 세로 정렬을 구분합니다. 행 전체 높이와 인접 콘텐츠의 읽기 관계를 기준으로 첫 줄·기준선·세로 중앙 중 적합한 방식을 고릅니다. 한 줄 값이 두 줄 식별 정보의 위쪽 절반에 놓이는 등 의도하지 않은 치우침을 확인합니다. 모든 표 셀을 중앙 정렬하는 규칙으로 바꾸지 않습니다.

**버튼의 상태:** 글자만 있는 상태와 아이콘·글자가 함께 있는 상태의 시각적 중심을 각각 확인합니다. 숨은 아이콘의 자리 때문에 글자가 치우치는지, 표시를 바꾸며 외곽 크기나 위치가 흔들리는지 함께 봅니다. 공간을 항상 유지하거나 항상 제거하도록 정하지 않습니다. 선택·미선택, 아이콘 유무, 긴 문구, 줄바꿈을 실제로 표시합니다.

**이름과 행동:** 필터링·항목 선택·위치 이동은 다른 행동입니다. 실제로 바뀌는 대상과 범위를 버튼 이름에 맞추고, 단순한 위치 이동을 조회 조건 변경이나 선택으로 오해하게 하지 않습니다. [제품 문구 기준](review-and-handoff.md#product-copy)에 따라 모호함을 긴 해설로 덮지 않습니다.

**정보의 역할:** 같은 정보인지 판단할 때 대상·필드 의미·값/상태와 표시 맥락을 함께 봅니다. [동일 정보 중복 판단](review-and-handoff.md#information-redundancy)을 공통 기준으로 사용합니다. 상세는 목록에서 생략된 정보·판단 근거·후속 행동을 제공해야 합니다. 반복이 대부분이면 상세의 존재·크기·표현 방식을 재검토하되 항목 식별과 판단에 필요한 맥락은 보존합니다.

**조합의 강약:** 단독으로 단정한 요소도 함께 놓으면 같은 강조가 경쟁하거나 간격·밀도가 어긋날 수 있습니다. 실제 콘텐츠와 영역·페이지에서 다시 판단합니다.

**단어 단위 줄바꿈:** [글자와 줄바꿈 기준](drafts-and-feedback.md)을 따라 단어 중간을 나누지 않습니다. 폭·글꼴·상태가 바뀌는 조합에서 긴 단어의 분리와 넘침을 함께 확인하고, 보존해야 할 내용을 임의로 자르지 않습니다.

## 조작 전후 흐름과 반응

상세로 안내할 때 필요한 만큼만 이동합니다. 목록 위치·선택 항목·상세의 관계와 복귀 경로를 확인합니다. 상세 제목을 무조건 화면 최상단으로 올리지 않습니다. 좁은 화면에서는 목록과 상세를 동시에 볼 수 없는 조건도 고려합니다.

스크롤·탐색·목록 복귀는 적은 항목이 한 화면에 들어오는 경우만으로 검증하지 않습니다. 여러 화면에 걸친 목록에서도 처음·중간·끝 항목을 선택해 상세를 읽고 원래 위치·초점으로 돌아오는 흐름을 봅니다. 콘텐츠 길이와 화면 높이도 맞춥니다. 시험용 데이터 규모와 한계는 화면 밖에서 기록하고 특정 건수를 모든 프로젝트에 강제하지 않습니다. 비교 목적이 다르면 작은 목록과 긴 목록 시험을 구분합니다.

버튼 수를 줄이는 것 자체를 목표로 삼지 않습니다. 항목 선택으로 상세를 여는 안은 발견 가능성·오조작·키보드 경로·선택과 실행의 의미까지 비교합니다. 사용자가 제안한 후보는 선택/위임 전까지 미선택으로 남깁니다.

| 후보 | 검토할 조건과 손실 |
|---|---|
| 행 안 펼침 | 추가 정보의 길이, 목록의 위치 변화, 다른 항목과의 비교, 접기와 복귀 |
| 고정 상세 영역 | 화면/페이지/스크롤 영역 중 고정 기준과 스크롤 주체를 먼저 확인합니다. 목록 가용 높이, 긴 상세 접근, 선택과 상세의 거리, 좁고 낮은 화면을 봅니다. |
| 별도 상세로 이동 | 본문의 길이와 독립 작업 필요성, 이동 폭, 원래 위치·초점의 복원 |

반응과 애니메이션은 상호작용을 설계할 때 함께 검토합니다. 버튼 누름·선택·펼침/접힘·내용 교체·시선 이동 같은 작은 변화도 빠뜨리지 않습니다. 무엇이 바뀌었는지와 다음 위치를 이해시키도록 적절한 전환을 사용하고, 즉각적인 상태 표시만으로 충분한 경우는 그렇게 판단한 이유를 남깁니다. 모든 변화에 같은 움직임을 강제하지 않습니다.

효과의 강도와 길이는 변화의 크기·거리·빈도에 맞춥니다. 연속 입력은 최신 상태를 즉시 반영하고 이전 효과를 취소/대체하여 대기열이나 조작 지연을 만들지 않습니다. 동작 감소 환경에서는 불필요한 이동 효과를 줄이면서 상태·정보·초점·행동을 유지합니다. 애니메이션으로 잘못된 배치나 과도한 이동을 가리지 않습니다.

반응을 추가한 뒤에는 앞서 줄이기로 한 중복 강조나 안내가 다시 생기지 않았는지 확인합니다. 일시적인 이동 안내와 지속적인 선택 표시의 역할을 구분하고, 추가 역할이 없는 중복은 공통 중복 기준으로 판단합니다. 특정 행 배경이나 체크 형태를 일괄 금지하는 뜻은 아닙니다.

## 판단·반복·이력

기본 판단 순서는 필수 정보·권한·조작 가능성 → 핵심 작업과 맥락 → 정렬·일관성 → 장식적 완성도입니다. 실제 사용자 제약과 관찰된 문제의 영향이 우선입니다. 종합 점수로 필수 결함을 상쇄하지 않습니다.

문제는 `수준·대상 → 관찰과 근거 → 작업/필수 조건의 영향 → 관련 하위·상위 → 변경 → 재확인 → 상태`로 필요한 만큼 기록합니다. 수정과 실제 화면·조작 확인은 구분합니다. [증거 수준과 인계](review-and-handoff.md)를 따르며 AI 검토를 미적 우수성이나 사용자 만족의 입증으로 쓰지 않습니다.

새 피드백·관찰된 결함이 반복 시작 조건입니다. 새 근거나 결함 감소 없이 같은 안을 오가면 중단하고 정체 이유·미정·마지막 유효 버전을 남깁니다. 한도 소진 시 임의 연장하지 않습니다. 필수 조건 회귀는 관련 사본을 복구/보완하고, 선택에 의존하지 않는 작업은 계속할 수 있습니다. 무제한 재귀·전수 조합·패턴 엔진·거대한 라이브러리를 만들지 않습니다.

최초 초안·의미 있는 중간안·최종 시안을 보존하고 함께 비교할 수 있게 제시합니다. 바뀐 점과 반영한 피드백을 연결하며 모든 미세 수정까지 전시하지 않습니다. 새 시험안을 과거 최종안에 덮어쓰거나 과거 검증을 새 버전의 통과로 소급하지 않습니다.
