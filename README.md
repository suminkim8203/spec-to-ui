# spec-to-ui · 명세서에서 대표 화면 설계까지

## 필수 프로그램

| 프로그램 | 필요한 이유 |
|---|---|
| Codex 앱 또는 CLI | `$spec-to-ui`를 읽고 명세서 해석과 화면 설계를 진행하는 AI 호스트입니다. 스킬과 로컬 파일을 사용할 수 있어야 합니다. |
| [Node.js 20 이상](https://nodejs.org/)과 npm/npx | 설치 도구를 실행할 때 필요합니다. |

설치 전에 아래 명령으로 Node.js와 npm/npx를 확인할 수 있습니다.

```sh
node --version
npm --version
npx --version
```

설치 도구는 Node.js 기본 모듈을 사용합니다. 추가 npm 의존성이나 Python은 필요하지 않습니다. 실제 화면 제작과 브라우저 확인에는 Codex 환경에서 사용할 수 있는 도구와 권한이 필요합니다.

## npm으로 설치하기

전역 CLI 설치 없이 스킬을 설치합니다.

```sh
npx --yes spec-to-ui@latest install
```

CLI를 전역에 설치해 사용할 수도 있습니다.

```sh
npm install -g spec-to-ui@latest
spec-to-ui install
```

설치 후 Codex에서 `$spec-to-ui`를 호출합니다. 스킬이 목록에 나타나지 않으면 Codex를 다시 시작해 주세요.

spec-to-ui는 요구사항 명세서를 바탕으로 UI 구조와 대표 화면을 설계하는 AI 스킬입니다. 필요한 기능은 정리했지만 화면 구성과 정보의 우선순위를 정하기 어려운 사용자를 돕습니다.

사용자와 권한, 페이지와 상태, 사용 흐름을 정리한 뒤 실제 참고 사례를 골라 대표 화면을 만듭니다. 사용자는 초안을 보며 유지할 부분과 고칠 부분을 판단하고, AI는 그 피드백을 관련 화면에 반영합니다.

## 주요 기능

| 기능 | 하는 일 |
|---|---|
| 명세서에서 화면 구조 정리 | 사용자와 권한, 필요한 페이지와 상태, 핵심 작업과 정보 우선순위를 연결합니다. |
| 실제 참고 사례 선정 | 원문과 화면을 확인하고 가져올 구성, 추천 이유와 손실을 설명합니다. |
| 대표 화면 제작 | 실제에 가까운 콘텐츠로 첫 화면을 만들고 필요한 경우 구성 방식이 다른 안을 비교합니다. |
| 피드백과 확장 | 유지·변경·미정을 구분하고 대표 화면에서 정한 규칙을 관련 페이지로 확장합니다. |
| 정렬과 줄바꿈 검토 | 행 전체의 정렬과 버튼의 선택 전후 상태를 확인하고 단어 중간 줄바꿈을 피합니다. |
| 목록과 상세의 관계 | 상세의 정보 가치, 선택과 초점, 이동 거리와 복귀 경로를 검토합니다. |
| 반응과 애니메이션 | 작은 상호작용도 함께 설계하고 연속 입력과 동작 감소 환경을 고려합니다. |
| 입력 요소의 디자인 | 필드·버튼뿐 아니라 펼친 달력과 선택 목록까지 화면의 디자인에 맞춥니다. 기존 입력 방식과 선택 범위를 보존합니다. |
| 의도와 사용성 확인 | 구조나 동작을 바꿀 수 있는 해석을 확인하고 실제 사용 중 예상되는 불편을 검토합니다. |

## 설치

기본 설치 위치는 `~/.agents/skills/spec-to-ui`입니다. 사용자 폴더에 설치하면 여러 프로젝트에서 사용할 수 있습니다.

현재 프로젝트에서만 사용하려면 해당 폴더에서 실행합니다.

```sh
npx --yes spec-to-ui@latest install --project
```

프로젝트 설치 위치는 `.agents/skills/spec-to-ui`입니다. Codex를 해당 작업 폴더에서 열어 사용합니다.

### 기존 설치 확인과 교체

```sh
npx --yes spec-to-ui@latest status
npx --yes spec-to-ui@latest install --replace
```

동일한 파일이 있으면 변경하지 않습니다. 다른 내용의 기존 폴더는 기본적으로 덮어쓰지 않으며, `--replace`를 지정한 경우에만 이전 폴더를 백업하고 교체합니다.

| 설치 방식 | 이전 폴더의 백업 위치 |
|---|---|
| 사용자 설치 | `~/.agents/skill-backups/spec-to-ui/` |
| 프로젝트 설치 | `.agents/skill-backups/spec-to-ui/` |

백업을 스킬 탐색 폴더 밖에 두어 이전 스킬이 중복으로 검색되는 일을 피합니다. 심볼릭 링크로 연결된 기존 설치는 자동 교체하지 않습니다.

### 소스에서 설치하기

저장소를 내려받은 뒤 `package.json`과 `bin/`이 있는 폴더에서 실행합니다.

```sh
git clone https://github.com/suminkim8203/spec-to-ui.git
cd spec-to-ui
node bin/cli.mjs install
```

이 방식에도 Node.js 20 이상이 필요합니다.

## 사용법

### 1. 명세서에서 첫 화면 설계

명세서 파일과 함께 다음처럼 요청합니다.

```text
$spec-to-ui 이 요구사항 명세서를 바탕으로 UI를 설계해 주세요.
필요한 화면과 사용 흐름을 정리하고, 실제 참고 사례를 비교한 뒤
대표 화면부터 보여 주세요.
```

명세서 해석, 화면 구조 정리, 참고 선정, 대표 화면 제작 순서로 진행합니다. 화면 구조에 영향을 주는 미정 사항은 사용자에게 확인합니다. 참고 선택이나 대표 화면 검토가 필요한 단계에서는 실제 차이를 보고 판단할 수 있도록 돕습니다.

### 2. 대표 화면에 피드백 반영

```text
$spec-to-ui 지금 대표 화면에서 날짜와 버튼 글자가 치우쳐 보입니다.
선택 전후 정렬을 확인하고, 상세를 읽은 뒤 목록으로 돌아오는 흐름도 검토해 주세요.
기존 정보와 날짜 입력 방식은 유지해 주세요.
```

피드백을 글꼴이나 색상 변경으로 바로 확정하지 않고, 문제가 생기는 요소와 주변 배치, 조작 전후 상태를 함께 살펴봅니다. 수정 범위와 관련된 화면에서 다시 확인합니다.

### 3. 이전 설계를 이어서 진행

```text
$spec-to-ui 이 명세서와 기존 설계 기록을 읽고 작업을 이어가 주세요.
이미 선택한 참고 방향과 정보 순서는 유지하고,
남은 상세 화면과 신청 오류 상태를 설계해 주세요.
```

명세서와 결정 기록, 시안의 위치를 함께 알려주면 기존 선택을 확인해 이어갈 수 있습니다. 스킬 자체에는 전용 상태 저장 파일이나 자동 복구 hook이 포함되어 있지 않습니다.

## 작동 구조

```text
요구사항 명세서
    ↓
사용자·권한·페이지·상태·흐름·정보 우선순위
    ↓
실제 참고 사례와 방향 선택
    ↓
대표 화면 제작과 사용자 피드백
    ↓
수정·관련 페이지 확장
    ↓
실제 화면과 조작 검토·인계
```

Codex가 스킬 지침을 읽고 설계 판단과 도구 사용을 수행합니다. 설치 도구는 파일 복사와 식별값 대조, 기존 폴더 보호와 백업 교체를 담당합니다.

## 결정과 작업 기록

- 사용자 결정, 문서와 코드에서 확인한 사실, AI 제안과 미확인을 구분합니다.
- 이미 확정한 선택은 유지하고, 새 피드백과 관련된 부분을 검토합니다.
- 의미 있는 초기·중간·최종 시안을 보존하고 변경 이유를 연결합니다.
- 실제로 확인한 화면과 동작, 남은 문제와 미검증 범위를 기록합니다.

작업을 이어갈 때는 관련 명세서와 결정 기록을 함께 제공합니다. 다른 채팅의 작업도 이어가려면 해당 자료의 위치를 알려주세요.

## 고급 사용

프로젝트 설치의 상태 확인과 교체도 같은 옵션을 사용합니다.

```sh
npx --yes spec-to-ui@latest status --project
npx --yes spec-to-ui@latest install --project --replace
```

스킬 폴더를 직접 지정할 수도 있습니다.

```sh
npx --yes spec-to-ui@latest install --target /path/to/spec-to-ui
npx --yes spec-to-ui@latest status --target /path/to/spec-to-ui
```

지정한 경로는 Codex가 읽는 스킬 위치에 있어야 합니다. 사용자 지정 경로의 백업은 대상 폴더의 두 단계 위에 있는 `skill-backups/spec-to-ui/` 아래에 남깁니다. `--target`과 `--project`는 함께 사용할 수 없습니다.

도움말과 버전은 다음 명령으로 확인합니다.

```sh
npx --yes spec-to-ui@latest --help
npx --yes spec-to-ui@latest --version
```

## 개발 및 검증

소스 폴더에서 명령과 배포 파일 목록을 확인할 수 있습니다.

```sh
node bin/cli.mjs --help
npm pack --dry-run --ignore-scripts
```

0.1.0 배포에서는 설치 도구의 5개 검사를 수행했습니다. 설치와 동일 파일의 재설치, 수정된 기존 파일의 보호와 백업 교체, 심볼릭 링크 보호, 잘못된 옵션 처리, 사용자 지정 경로와 미설치 상태 조회를 확인했습니다.

공개 레지스트리에서 내려받은 tarball은 준비한 파일과 바이트 단위로 같았고 SHA-512 식별값도 일치했습니다. 사용자 npm 인증 정보가 없는 새 임시 환경에서 `npx` 설치를 실행해 스킬 문서 7개와 라이선스를 대조했습니다. 새 Codex 채팅에서 자동 발견과 실제 설계까지 이어지는 흐름은 별도 검증이 필요합니다.

설계 흐름은 장비 대여와 문화공간 예제로 검토했습니다. 이 결과를 모든 제품의 디자인 품질, 실제 기기와 보조기기 동작, 사용자 만족의 보증으로 확대하지 않습니다.

```text
skill/                       스킬 진입점·설정·참고 문서·라이선스
bin/cli.mjs                  설치·상태 확인·백업 교체 명령
skill-manifest.json          설치할 파일의 SHA-256 식별값
package.json                 npm 메타데이터와 배포 파일 목록
README.md / README.ko.md      설치와 사용 안내
LICENSE                      MIT 라이선스
```

스킬과 설치 도구를 배포합니다. 과제 제출문, 개인 대화와 인증 정보, 예제의 내부 작업 기록은 npm 패키지에 포함하지 않습니다.

## 문제 해결

| 상황 | 확인할 내용 |
|---|---|
| 스킬이 보이지 않음 | `status`로 설치 위치를 확인하고 Codex를 다시 시작해 주세요. 프로젝트 설치라면 해당 폴더에서 Codex를 열었는지도 확인합니다. |
| 기존 스킬이 있어 설치가 멈춤 | 기본 보호 동작입니다. 이전 폴더를 백업하고 교체하려면 `install --replace`를 사용합니다. |
| 심볼릭 링크 때문에 교체가 멈춤 | 설치 도구는 연결된 기존 폴더를 유지합니다. 링크 대상과 관리 방식을 확인한 뒤 설치 위치를 정해 주세요. |
| 파일 검증에 실패함 | 기존 설치를 덮어쓰지 않고 중단합니다. 패키지를 다시 내려받아 확인해 주세요. |
| 명세서의 중요한 내용이 미정임 | 화면 구조나 핵심 작업을 바꾸는 사항만 먼저 정하고, 영향 없는 설계는 진행할 수 있습니다. |
| npm 설치만 했는데 화면이 만들어지지 않음 | 설치는 스킬 파일을 준비하는 단계입니다. Codex에 명세서를 제공하고 `$spec-to-ui`를 호출해 주세요. |
