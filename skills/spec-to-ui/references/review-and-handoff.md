# 화면 검토와 구현 인계

초안 검토와 전체 확장 후 마무리에 사용합니다. 자동 검사를 디자인 품질 점수로 바꾸지 않습니다.

## 실제 화면에서 순서대로 검토

| 순서 | 볼 내용 | 근거 |
|---|---|---|
| 큰 구조 | 핵심 작업·먼저 볼 정보·탐색·역할별 행동·불필요한 소개 | 명세서/결정과 화면의 연결 |
| 관계·정렬·여백 | 묶음·시선 순서·버튼과 정보 거리·반복 역할의 기준선 | 실제 위치·긴 콘텐츠 |
| 글자·색·아이콘 | 위계·강조 면적·의미·한글/숫자·자산 로딩 | 렌더링과 필요한 측정 |
| 상태·작은 화면·흐름 | 빈 결과·로딩·오류·권한·긴 제목·좁은 폭·키보드/초점·글자 확대·선택 후 복귀 | 표시/조작한 범위 |
| 각 상호작용의 반응 | 상태 전달·전환·연속 입력·동작 감소·정보 유지 | 설계 단계부터 실제 동작까지 |

구체적인 정렬·버튼 상태·상세 가치·이동·애니메이션은 [의미 단위 조합과 검증](composition-and-validation.md)의 공통 기준을 사용합니다. 마지막 행은 끝에 효과를 붙이라는 순서가 아니며, 각 상호작용과 함께 확인합니다. 필수 조건·충돌·반복 한도도 같은 문서를 기준으로 판단합니다.

<a id="information-redundancy"></a>
## 동일 정보 중복 판단

설계·초안·피드백·최종 검토에서 같은 기준을 사용합니다.

1. 같은 정보·상태·수량·설명이 배경, 버튼 강조, 배지, 보조 문구, 별도 요약 등에 나타나면 각 표현이 추가하는 정보·행동상 역할·맥락을 확인합니다.
2. 새 역할이 없는 반복은 가장 적절한 표현을 중심으로 통합/삭제하는 안을 권합니다. 공간을 채우거나 친절해 보이려고 이미 명확한 내용을 다시 설명하지 않습니다. 목록과 상세, 전체 요약과 개별 판단, 오류·중요 행동 확인처럼 역할이 다른 반복은 유지할 수 있습니다.
3. 필요한 라벨과 의미에 맞는 보조기기용 selected/pressed/checked 등의 상태·키보드 초점은 보존합니다. 시각 표현을 줄인 결과 색만 남지 않도록 형태·선택 표시·컨트롤 상태 등 적절한 단서를 검토합니다. 모든 반복을 금지하거나 ‘현재 선택’ 같은 특정 문구를 항상 불필요하다고 정하지 않습니다.
4. 실제 화면의 선택 전후·다른 항목 선택·키보드·좁은 화면에서 줄인 모습과 필요한 정보/단서의 보존을 확인합니다. 사용자 예시는 판단 사례이며 해당 컴포넌트를 직접 확인했다는 증거가 아닙니다. 사용자에게는 덜어 낸 모습과 유지한 안내의 이유를 필요한 만큼만 설명합니다.

<a id="product-copy"></a>
## 제품 화면 문구와 작업 설명

제품 화면에 문장을 넣기 전에 최종 사용자가 어떤 판단·행동을 위해 읽어야 하는지 확인합니다. 작업상 역할이 없으면 삭제하며, 빈 공간이나 친절한 인상을 위해 문장을 채우지 않습니다.

- 개발 방식·시안 버전·합성/예시 여부·미연결 범위·브라우저에서만 동작함·정책 미정·구현/검증 상태는 대화나 별도 검토 기록에 둡니다. 제품의 배너·소개·각주·반복 안내로 자동 출력하지 않습니다.
- “기간과 상태를 비교합니다”, “상세에는 내용을 모았습니다”, “선택하면 아래에 표시됩니다”처럼 화면 구성을 해설하거나 보이는 조작을 되풀이하는 문장은 기본적으로 넣지 않습니다. 이를 삭제한 자리에 다른 해설을 만들어 넣지 않습니다.
- 버튼·필드·상태 라벨과 필요한 오류/복구·입력 조건·업무상 주의는 실제 작업에 필요한 내용으로 유지합니다. 모든 안내나 접근 가능한 이름을 없애라는 규칙은 아닙니다. 모호한 버튼은 보조 설명을 늘리기 전에 이름과 행동의 대응을 고칩니다.
- 시뮬레이션이라는 사실과 미검증을 숨기거나 실서비스라고 소개하지 않습니다. 고지의 위치를 화면 밖으로 분리합니다. 사용자가 제품 내 고지를 명시적으로 요청하거나 실제 운영 요구로 정한 경우에만 그 범위에 맞춰 둡니다.

## 화면 표현의 적합성

“AI스럽지 않게”를 특정 색·그라디언트·카드의 전면 금지로 해석하지 않습니다. 다음을 실제 화면에서 살피되 해당하지 않으면 문제를 만들어내지 않습니다.

- 관계가 다른 내용을 같은 카드/버튼/섹션으로 반복하는지 봅니다.
- 중요 정보와 보조 정보가 같은 크기·면적·강조로 경쟁하는지 봅니다.
- 작업과 관계없는 홍보·긴 소개가 핵심 콘텐츠를 밀어내는지 봅니다.
- 선·면·장식을 줄인 결과 필요한 구분이나 내용의 성격까지 사라지는지 봅니다.
- 여백이 관계와 순서를 설명하는지, 무작정 넓거나 좁은지 봅니다.
- 일관성과 페이지 목적에 따른 차이가 함께 있는지 봅니다.

숫자보다 결함을 기록합니다. 예: “좁은 화면에서 첫 항목 제목이 긴 소개 아래로 밀립니다 → 소개를 줄이고 제목·상태를 먼저 배치하는 안입니다.” 이는 해당 화면의 관찰/제안이며 보편 규칙이 아닙니다.

대비율·조작 영역·접근성 수치를 쓰려면 대상 플랫폼과 현재 적용 기준의 공식 원문을 확인하고 실제 값으로 측정합니다. 일부 색쌍·AX 구조·키보드 검사만으로 전체 접근성 준수를 선언하지 않습니다. 좁은 iframe·브라우저 크기 검사는 실제 기기 시험과 구분합니다.

## 증거를 분리하기

| 수준 | 말할 수 있는 범위 |
|---|---|
| 설계 제안 | 어떤 이유로 어떤 구성을 제안했는지 |
| 코드/파일 확인 | 작성된 구조·설정·자산·명세 연결 |
| 실제 화면 확인 | 관찰한 화면·상태·폭에서 보인 관계·잘림·로딩 |
| 동작 확인 | 실행한 입력·상태 변화·이동·실제 연동 결과 |
| 사용자 판단 | 실제 발언으로 확인한 선택·불만·만족의 범위 |

검사 수·문법 통과·서버 응답·AI 검토는 위 수준을 대신하지 않습니다. 특정 부분 선택과 전체 UI/원본 적용 승인은 다릅니다. 가상 응답 결과를 실제 사용자 검증에 넣지 않습니다.

독립 검토가 요청되었거나 복잡한 설계 평가에 유용하고 위임이 허용되면, 요청·명세서·현재 결정·실제 화면 등 필요한 원자료만 전달합니다. 기대 답·이전 판정·의심 결함을 정답으로 주지 않습니다. 선택 후 검토 순서를 정했다면 지킵니다. 수정 후 관련 화면을 다시 확인하며 AI 검토를 미적 만족의 증명으로 표시하지 않습니다.

## 구현을 이어갈 때

현재 변경에 필요한 요구·흐름·데이터·권한/인증·기술/서비스·연동·기존 제약을 확인합니다. 범위를 바꿀 미정은 짚고 독립 작업은 계속합니다. 정적 시안에 운영 DB·인증 기술까지 선택하도록 요구하지 않습니다.

관련 라우트·UI 호출·서버/인증 설정을 필요한 범위까지 읽습니다. 라이브러리 일반 기능, 활성화된 설정, 사용자 흐름의 실제 구현을 나눕니다. 일부 파일에서 찾지 못한 것은 미구현 확정이 아닙니다. 명세서에 적혔다고 구현됐다고 하지 않습니다.

사용자의 보존·미리보기·적용 조건을 따릅니다. 디자인 선택 자체는 원본 변경 권한이 아니지만 이미 승인된 범위에 재승인을 추가하지 않습니다. 기존 서버/원본 조작 권한이 없으면 별도 초안으로 진행합니다. 연동 없는 로그인·승인·저장 버튼은 대화·검토 기록에서 시뮬레이션 범위를 밝히며 제품 본문에 내부 작업 설명을 덧붙이지 않습니다.

<a id="design-record"></a>
## DESIGN.md와 요구사항 기록

프로젝트의 기존 DESIGN.md나 디자인 문서를 먼저 읽고 재사용합니다. 새 프로젝트라면 방향을 채택한 시점부터 DESIGN.md에 실제 값으로 배치·정보 위계·글꼴/굵기/크기·색 역할·간격·컨트롤·상태·반응형·모션 규칙을 정리합니다. 열린 달력과 선택 목록도 포함합니다. AI 제안·사용자 확정·명시적 위임에 따른 선택·미정을 구분하고 관련 요구 ID를 연결합니다. 내부 설계 파일을 제품 본문의 설명으로 출력하지 않습니다.

목표·기능·권한·업무 규칙·흐름·인수 기준은 기존 명세서에서 관리합니다. SpecFrame 상태를 사용하는 프로젝트는 그 방식을 유지하며 별도의 최신 명세서를 만들지 않습니다. 요구가 바뀌면 관련 DESIGN.md·화면과 인수 기준을 함께 갱신합니다. 디자인 선택과 코드 작성·검증·사용자 승인 사실을 구분합니다.

다른 스킬의 제안은 적용한 내용만 DESIGN.md에 반영합니다. 검색 결과나 원본 지침 전문을 복사하거나 두 번째 팔레트·글꼴 체계를 자동 생성하지 않습니다. 세부 검증 로그·캡처는 별도 근거로 두고 중요한 결과와 미검증만 연결합니다. 작은 수정에는 기존 항목의 갱신으로 충분합니다.

## 인계할 최소 내용

필요한 만큼 한 문서로 정리합니다.

- 접근 자료·현재 범위·최신 확정/위임·미정입니다.
- 요구 → 역할/페이지/상태/행동 연결, 흐름과 정보 우선순위입니다.
- 참고 원문·관찰 범위·옮긴 구성·제외한 부분입니다.
- 선택 시안과 유지/변경, 공통 규칙과 페이지별 차이입니다.
- 자산 출처·조건/고지, 확인·미검증, 다음 작업입니다.

마지막 응답에는 시안을 열어 볼 수 있게 하고 중요한 변화·확인 범위·남은 판단을 짧게 말합니다. 긴 로그는 별도 근거로 둡니다. 원본 적용·설치·슬래시 메뉴 호출·배포를 시험하지 않았다면 완료로 적지 않습니다.
