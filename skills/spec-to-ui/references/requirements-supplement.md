# 명세서 보충과 UI 설계 복귀

요구 누락·충돌이 현재 화면·권한·핵심 흐름을 결정할 수 없게 할 때 사용합니다. 명세서 분량이나 디자인 용어의 유무를 기준으로 삼지 않습니다. 배치 선택은 시안으로, 정렬·팝업 잘림·오동작은 설계/구현 수정으로 해결합니다. 의도가 불명확하면 기존 대화·이미지·코드를 먼저 확인합니다.

## 보충 시작

빠진 내용과 확인 범위 → 영향을 받는 화면·행동 → 지금 결정할 이유 → 추천안·중요한 손실 → 독립적으로 계속할 작업을 짧게 설명합니다. 사용할 수 있는 SpecFrame은 [형제 폴더](../../specframe/SKILL.md)에서 읽습니다. 단순 스킬 사용을 다시 승인받지는 않지만 새 업무 규칙을 추측으로 확정하지 않습니다.

SpecFrame에는 최신 명세서·요구 ID·결정과 위임 범위, 관련 화면/코드, 쟁점·보존 조건·복귀할 작업을 전달합니다. 필요한 원자료를 읽고 기존 상태를 재사용합니다. 이미 답한 질문이나 영향 없는 요구를 처음부터 묻지 않습니다. 사용할 수 없으면 그 사실을 밝히고 spec-to-ui가 직접 누락 요구와 추천안을 설명해 사용자 판단을 받습니다. 이를 SpecFrame 실행이라고 하지 않습니다.

## 검토와 승인

SpecFrame의 전체 운영 계약과 검토·상태 저장·복구 절차를 따릅니다. 보충은 관련 요구뿐 아니라 영향받는 흐름·예외·인수 기준에도 반영합니다. 실제 의미가 바뀌면 기존 승인을 유지하지 않습니다. 추천안 선택의 위임과 최종 명세서 승인을 구분하고, 검토한 전체 현재 명세서를 사용자에게 제시한 뒤 실제 확인이 있어야 승인 처리합니다.

요구를 정하는 중요한 질문이 남아 있으면 그 결정에 의존하는 설계·구현은 기다리고, 결정과 독립적인 작업은 계속합니다. 과거 사용자 응답·테스트용 가상 응답·승인 플래그의 존재를 새 실제 승인으로 꾸미지 않습니다. 사용자에게 시험용 응답을 받았다면 그 범위와 실제 사용자 검증을 구분합니다.

## 복귀

이 개발 묶음의 SpecFrame 사본은 승인 후 **spec-to-ui의 진행 중이던 UI 설계**로 돌아오도록 조정되어 있습니다. 요구 보충이 끝났다고 바로 구현·다른 스킬 설치로 넘어가지 않습니다. 기존 전역 SpecFrame이나 다른 스킬의 계약·hook을 수정하지 않습니다.

복귀 전에 현재 승인·명세서 본문·남은 미정과 변경 영향을 확인합니다. 본문이 맥락에 없으면 다시 읽습니다. 적용할 화면·DESIGN.md 규칙·인수 기준을 갱신하고 바뀐 흐름을 검증합니다. 전체 디자인을 초기화하지 않으며 필요한 전달이 끝나지 않았으면 준비와 실제 복귀를 구분합니다. 상태 소유 세션이 다르면 올바른 소유·경로를 확인하고 복구 결과를 추측하지 않습니다.
