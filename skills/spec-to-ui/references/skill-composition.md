# 스킬 조합

spec-to-ui가 설계 진행을 조율하고 필요한 보조 지침만 읽습니다. 다음 경로는 이 문서를 기준으로 하며 전역 스킬 설치를 변경하지 않습니다.

| 구성 | 진입 자료 | 적용 범위 |
|---|---|---|
| SpecFrame | [형제 스킬](../../specframe/SKILL.md) | 요구 부족·충돌의 보충과 검토·승인입니다. [보충과 복귀](requirements-supplement.md)를 따릅니다. |
| design-taste-frontend | [형제 스킬](../../design-taste-frontend/SKILL.md) | 필요한 시각 방향과 구성·활자·이미지·모션 보강입니다. 소개 페이지와 작업 화면의 분기를 따릅니다. |
| ui-ux-pro-max | [형제 스킬](../../ui-ux-pro-max/SKILL.md) | 현재 폼·반응형·상호작용 등 문제의 검색 지침입니다. 실행 경로는 실제 스킬 폴더에서 확인합니다. |
| DESIGN.md | 프로젝트의 기존 문서 또는 [기록 기준](review-and-handoff.md#design-record) | 채택 규칙의 기록·재사용입니다. 별도 설치 스킬이 아닙니다. |
| Refero Styles 등 | [참고 선정 기준](reference-selection.md) | 실제 원문과 화면의 열람·비교입니다. 필수 가입·유료 이용을 전제로 하지 않습니다. |

사용자의 요구·명세서·확정 디자인·실행 환경 제약을 보조 스킬의 추천에 대조합니다. 중요한 변경과 손실은 설명하고 확인하며 사소한 승인 범위 조정은 자율적으로 처리합니다. 자체 스타일의 요구를 맞추려고 콘텐츠·기능·브랜드 주장을 추가하거나 삭제하지 않습니다. 필요한 사용성·접근성 문제는 근거와 보완안으로 짚습니다.

이미 채택한 디자인에는 새로운 방향 추출이나 두 번째 디자인 시스템 생성을 강제하지 않습니다. taste의 자체 이미지·모션·장식 수량 규칙이 승인된 구조와 충돌하면 해당 규칙을 제외하고 이유를 남깁니다. ui-ux-pro-max의 검색 결과는 DESIGN.md의 새 확정값이 아니며 적용한 결과만 기록합니다. 일부만 적용했다면 원본 전체 절차 충족으로 보고하지 않습니다.

스크립트는 해당 스킬의 실제 위치에서 실행합니다. 다른 호스트용 환경 변수나 개인 경로를 추측하지 않습니다. 브라우저 조작은 현재 허용된 도구를 사용하며 CDP 기반 inspector가 허용되지 않으면 가능한 화면·조작 확인으로 대체하고 inspector 미실행을 밝힙니다. 조합 검증을 위해 새 프레임워크·브라우저·네트워크 서비스를 무단 설치하지 않습니다.

보조 스킬이 없으면 다른 전역 설치본을 자동 선택하거나 설치하지 않습니다. 누락과 대안을 알리고 의존하지 않는 작업은 계속합니다. 사용자가 기존 설치본 재사용을 명시한 경우 실제 경로·버전을 확인해 읽을 수 있습니다. 스킬이 없거나 도구가 실행되지 않은 상태를 성공으로 기록하지 않습니다.

이번 묶음에서 SynFrame·Sites·Humanizer는 필수 의존성이 아닙니다. 필요한 구현 도구는 이미 승인한 작업 범위와 실행 환경에 맞게 사용합니다. 스킬 호출 자체는 원본 변경·설치·유료 연결·배포의 권한을 추가하지 않습니다.
